# Attestation Protocol Ordering Examples

Example attestation protocol analyses using the AttestationProtocolOrdering Coq library. 
Orders attestation protocols by their difficulty to attack.

## Meta

- Additional dependencies: `AttestationProtocolOrdering`

## Examples
| Directory | Design choice evaluated |
| --- | --- |
| `smmExamples` | Static vs dynamic root of trust, and measuring vs containing system management mode |
| `teeExamples` | Direct TEE attestation vs delegating attestation to a vendor SDK and cloud proxy |
| `vcExamples` | Vulnerable component limits protocol strength |

## Building and installation instructions


### Prerequisites
Clone the AttestationProtocolOrdering repository at
git@github.com:ku-sldg/protocol-ordering.git
and follow the build instructions in the README.md to install 
a local version of the library.


Download the Copland Collection at
https://ku-sldg.github.io/copland/resources/copland-collection.tgz
and follow the installation instructions in the README.md to install
Chase and the Copland theory.

### Provided Examples
Generate and compile the provided examples with:
```
(cd scripts/ ; bash setup.sh <foldername>)
make
```
where `<foldername>` is is any directory listed under [Examples](#examples).
`setup.sh` performs three steps:

1. Runs Chase on every protocol and convert the attack graphs to Coq
3. Generates the ordering results for the given specification file
4. Rewrites `_CoqProject` to point at `<foldername>`

### Example Layout
Each example directory contains the following files:

| File | Contents |
| --- | --- |
| `chase-inputs/<basename>.cop` | A Copland protocol |
| `chase-inputs/<basename>.gln` | The systems assumptions for that protocol: component dependencies, uncorruptible components, the adversary's goal |
| `chase-inputs/Makefile.chase`* | Chase makefile |
| `chase-inputs/thy.gli`* | Chase-Copland theory |
| `chase-outputs/<basename>_chase.xhtml`** | The protocol's attack graphs in XHTML |
| `<basename>.v`** | The protocol's attack graphs in Coq |
| `components.v` | The type of system components and its decidable equality proof |
| `advOrder.v` | The adversary action ordering and a proof that its closure is antisymmetric |
| `myOrdering.spec` | The ordering results to prove |
| `myOrderingHelper.v`** | The `leq`, `tleq` and `tstar` lemmas (and their negations) that the ordering results are proved from |
| `myOrdering.v`** | The ordering results proved as lemmas |
| `README.md` | The design choice evaluated and an explanation of the results |

\* Should not be edited
\*\* Generated by `setup.sh` script

### User-Defined Examples
Copy the `template` directory and give it a name of your choosing. 
```
cp -r template/ <foldername>
```

Add pairs of files with names in the form `<basename>.cop` and `<basename>.gln` 
to the `chase-inputs` directory containing a Copland protocol and its corresponding 
system assumptions respectively. 

Then, complete the `components.v` file by defining a type that represents the set of 
system components appearing in your protocols and completing a proof that this 
type has decidable equality (proof provided in template file). 

Next, complete the `advOrder.v` file by adding a list of pairs of time-constraint tagged 
adversary event labels asserting judgments about which adversary actions are less difficult 
than others. Complete a proof that the adversary ordering is antisymmetric (proof provided
in template file).

Finally, list the desired comparisons in `myOrdering.spec`. The spec file includes lines in 
the following form:
* Alias `NAME := SIDE`: Define `NAME` as `SIDE` so that later lines can use `NAME` as a side.
* Verdict `NAME : ORDER LHS RHS`: Define a lemma `NAME` stating the ordering verdict between
  `LHS` and `RHS` under `ORDER`. `NAME :` is optional (default lemma name is `ORDER_LHS_vs_RHS`).

Generate and compile your example with:
```
(cd scripts/ ; bash setup.sh <foldername>)
make
```

To analyze your protocols in other ways, create a Coq file. Import the AttestationProtocolOrdering 
library, your components, your adversary action ordering, and the generated attack graphs with:
```
Require Import AttestationProtocolOrdering.<libname>.
Require Import ProtocolOrderingExamples.components.
Require Import ProtocolOrderingExamples.advOrder.
Require Import ProtocolOrderingExamples.<basename>.
```
Options for `<libname>` are *attackgraph*, *attackgraph_normalization*, *attackgraph_adversary*,
*adversary_ordering*, *make_adversary_ordering*, *attackgraph_ordering*, *set_ordering*, 
*set_relationship*, *trace_ordering*, and *trace_relationship*.




## Documentation

### Scripts
All scripts are unverified and contain only crude error handling. They are intended only
as a convenience.

`xhtml2coq.py`: Convert Chase output in XHMTL to attack graphs in Coq.

`getAttacks.sh`: Find and convert attacks of a specified protocol.

`getAllAttacks.sh`: Find and convert attacks of all protocols.

`handleInput.py`: Read attack graphs, adversary orderings, and spec files.

`kuhn.py`: Find a witness or Hall violator for the `preceq` relationship using Kuhn's algorithm.

`writeOrderProofs.py`: Write the helper and verdict proofs.

`genOrdering.py`: Generate `myOrderingHelper.v` and `myOrdering.v` from `myOrdering.spec`

`genCoqProject.py`: Generate a `_CoqProject` file for a given foldername.

`setup.sh`: Bash script to get all attacks and generate `myOrderingHelper.v`, `myOrdering.v`, and `_CoqProject`.
